## Phase 2: Code Structure & Duplication

### 2.1 Extract `run_build` into focused functions
Split the 386-line function into:
- `_detect_source_type(download_files, source) -> str`
- `_find_tool_files(download_files, source_type) -> tuple[Path, Path]`
- `_merge_to_apk(input_apk, app_name) -> Path`
- `_strip_arch_libs(input_apk, arch)`
- `_repair_apk(app_name, version, input_apk)`
- `_run_patch(cli, patches, input_apk, output_apk, is_morphe, exclude_patches, include_patches)`
- `_sign_apk(output_apk, signed_apk)`

### 2.2 Consolidate source type detection
Three independent implementations:
- `__main__.py:36-61` (inline, 25 lines)
- `utils.py:573-589` (`detect_source_type`, never called)
- `utils.py:201` (`is_morphe_cli` check)

Consolidate into a single `detect_source_type()` in `utils.py` and call it from `__main__.py`.

### 2.3 Consolidate CLI version detection
Duplicate in `__main__.py:292-296` and `utils.py:202-206`. Extract to `utils.py` as `is_newer_revanced_cli(cli_name: str) -> bool`.

### 2.4 Extract `fetch_soup()` helper
BeautifulSoup fetch+parse pattern appears 17+ times. Extract to `src/utils.py`:
```python
def fetch_soup(url: str, headers: dict = None) -> BeautifulSoup:
    response = session.get(url, headers=headers or {})
    response.raise_for_status()
    return BeautifulSoup(response.content, "html.parser")
```

### 2.5 Consolidate version parsing

### 2.6 Remove `run_process` dead catch-re-raise
`utils.py:156-162` — catches exceptions and re-raises unchanged. Remove the try/except.

### 2.7 Remove `get_supported_version` wrapper if unused

## Phase 3: Error Handling & Reliability

### 3.1 Add retry logic to `download_resource`
`downloader.py:9-31` — zero retries. Add:
- Configurable max retries (default 3)
- Exponential backoff
- Timeout parameter (default 60s)
- Write to temp file, rename on success
- Log retry attempts

### 3.2 Fix `download_platform` exception handling
`downloader.py:186-188` — catches all exceptions, returns opaque tuple. Improve: log traceback, don't catch `KeyboardInterrupt`/`SystemExit`.

### 3.3 Fix subprocess resource leak in `run_process`
`utils.py:127-162` — use `try/finally` to close stdout and wait for process on exception.

### 3.4 Make `run_build` error handling consistent
Standardize: raise structured exceptions, catch per-architecture in `main()`.

### 3.5 Add startup validation
In `main()`, verify `java`, `zip`, `apksigner` are available before building.

### 3.6 Fix error truncation
`apkmirror.py:453` and `uptodown.py:35,96` — log full error instead of 50 chars.

### 3.7 Log earlier download failures
`downloader.py:178-180` — log each failure, not just the last one.

## Phase 4: Scraping Improvements

### 4.1 Add `fetch_soup()` helper (from 2.4)
Used across all scrapers to replace duplicated fetch+parse pattern.

### 4.2 Fix apkmirror redundant requests
`apkmirror.py` makes 6-15 sequential HTTP requests per download:
- Cache main page soup within `get_download_link` (reuse for build number lookup + release discovery)
- Cache release page soup (avoid re-fetching in fallback loop)
- Limit URL pattern attempts in fallback loop (currently tries 4 patterns x N version parts)

### 4.3 Fix uptodown slug caching
`uptodown.py` — `get_latest_version` and `get_download_link` both independently call `generate_possible_uptodown_names` and iterate the same list. Cache the resolved slug between calls.

### 4.4 Add input validation to scrapers
- `apkpure.py`: Validate required config keys (`name`, `package`) before URL construction
- `aptoide.py`: Guard empty `datalist` results
- `apkmirror.py`: Validate config has `org`, `name`, `type`, `dpi`

### 4.5 Unify error return semantics across scrapers
Current inconsistency:
- `apkmirror.py` returns `None` on failure
- `uptodown.py` raises `Exception` in `get_latest_version`
- `aptoide.py` raises `ValueError`
- `apkpure.py` returns `None`

Standardize: all scrapers return `None` on expected failures (version not found), raise on unexpected errors (network, parsing).

### 4.6 Reduce apkmirror URL pattern spam
`apkmirror.py:313-458` tries up to 4 URL patterns per version part. Add early exit after first successful page fetch, and limit version part stripping to 2 levels.
